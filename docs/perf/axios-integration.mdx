## Prerequisites

- `@react-native-firebase/app` and `@react-native-firebase/perf` installed per [Performance Monitoring usage](/perf/usage) (native config, rebuild, and Android Performance Monitoring Gradle plugin or Expo config plugin).
- [Axios](https://github.com/axios/axios) installed in your app (`npm install axios` or `yarn add axios`).

# Axios

The [Axios library](https://github.com/axios/axios) allows you to easily send HTTP requests via your
React Native application. Axios provides functionality allowing all requests & responses to be intercepted, exposing
metadata which can be hooked into the Performance Monitoring library.

`httpMetric` constructs an `HttpMetric` for the request URL and HTTP method. `HttpMethod` is the string union of allowed verbs. See [HTTP Request Tracing](/perf/usage#http-request-tracing) for the full metric helpers.

## Request Interceptor

Before HTTP requests are sent out of the React Native environment, a callback can be attached to the `request`
property on the axios instance. At this point, a new HTTP metric can be defined on the Performance Monitoring library:

```js
import axios from 'axios';
import { getPerformance, httpMetric } from '@react-native-firebase/perf';

axios.interceptors.request.use(async function (config) {
  try {
    const method = /** @type {import('@react-native-firebase/perf').HttpMethod} */ (
      String(config.method || 'GET').toUpperCase()
    );
    const httpMetricInstance = httpMetric(getPerformance(), config.url, method);
    /** @type {any} */
    const requestConfig = config;
    requestConfig.metadata = { httpMetric: httpMetricInstance };

    httpMetricInstance.putAttribute('client', 'axios');

    httpMetricInstance.start();
  } finally {
    return config;
  }
});
```

This callback attaches the HTTP metric returned onto the request metadata, which can later be used on an
incoming response.

## Response Interceptor

Similar to the request interceptor, we can also hook into all responses from the HTTP calls. The response
interceptor can accept two callbacks, one for successful responses and one for requests which failed:

```js
import axios from 'axios';
import { getPerformance, httpMetric } from '@react-native-firebase/perf';

axios.interceptors.request.use(async function (config) {
  try {
    const method = /** @type {import('@react-native-firebase/perf').HttpMethod} */ (
      String(config.method || 'GET').toUpperCase()
    );
    const httpMetricInstance = httpMetric(getPerformance(), config.url, method);
    /** @type {any} */
    const requestConfig = config;
    requestConfig.metadata = { httpMetric: httpMetricInstance };
    httpMetricInstance.start();
  } finally {
    return config;
  }
});

axios.interceptors.response.use(
  async function (response) {
    try {
      /** @type {any} */
      const requestConfig = response.config;
      const metric = requestConfig.metadata.httpMetric;

      metric.setHttpResponseCode(response.status);
      metric.setResponseContentType(response.headers['content-type']);
      metric.stop();
    } finally {
      return response;
    }
  },
  async function (error) {
    try {
      /** @type {any} */
      const requestConfig = error.config;
      const metric = requestConfig.metadata.httpMetric;

      // Network / timeout errors have no response; still stop() so the metric finishes.
      if (error.response) {
        metric.setHttpResponseCode(error.response.status);
        metric.setResponseContentType(error.response.headers['content-type']);
      }
      metric.stop();
    } finally {
      return Promise.reject(error);
    }
  },
);
```

All outbound requests sent from Axios will appear in your Firebase console, detailing information such as
how long the request took, response codes & more. Such data can give you greater insight into the performance
of your application via any external APIs you may be using.
