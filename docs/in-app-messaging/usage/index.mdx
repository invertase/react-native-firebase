## Prerequisites

- `@react-native-firebase/app` installed and native config completed per [Getting Started](/) (Android `google-services.json`, iOS `GoogleService-Info.plist`, Expo config plugin, or React Native CLI setup). From v26, New Architecture is required for packages with a native bridge.
- `@react-native-firebase/analytics` installed. In-App Messaging lists Analytics as a peer dependency (Google Analytics must be enabled on the Firebase project).
- Install In-App Messaging: `npm install --save @react-native-firebase/in-app-messaging` or `yarn add @react-native-firebase/in-app-messaging`, then rebuild native apps (`cd ios && pod install` on iOS).
- Author campaigns in the [Firebase Console In-App Messaging](https://console.firebase.google.com/project/_/inappmessaging) tab before expecting messages on device. This package is **not** Cloud Messaging (`@react-native-firebase/messaging` / FCM).

Example Expo Router screen: https://github.com/invertase/react-native-firebase/blob/main/test-expo/app/in-app-messaging.tsx

# Installation

This module requires that the `@react-native-firebase/app` module is already setup and installed. To install the "app" module, view the
[Getting Started](/) documentation.

This module also requires that the `@react-native-firebase/analytics` module is already setup and installed. To install the "analytics" module, view its [Getting Started](/analytics/usage) documentation.

```bash
# Install & setup the app module
yarn add @react-native-firebase/app

# Install the analytics module (peer dependency)
yarn add @react-native-firebase/analytics

# Install the in-app-messaging module
yarn add @react-native-firebase/in-app-messaging

# If you're developing your app using iOS, run this command
cd ios/ && pod install
```

The manual installation pages for [iOS](/in-app-messaging/usage/installation/ios) and [Android](/in-app-messaging/usage/installation/android) are legacy and only apply to React Native 0.59 and earlier. For a supported setup, use the autolinking steps above and [Getting Started](/).

**Platform notes:** The firebase-js-sdk does not ship a modular public API for this product (`firebase/in-app-messaging` does not exist). Every export below is React Native Firebase only. In-App Messaging supports only the **default** Firebase app (`hasMultiAppSupport: false`). There is no In-App Messaging emulator and no `connect*Emulator` helper for this package. Do not confuse this package with [Cloud Messaging](/messaging/usage).

React Native Firebase exports runtime `getInAppMessaging`, `isMessagesDisplaySuppressed`, `setMessagesDisplaySuppressed`, `isAutomaticDataCollectionEnabled`, `setAutomaticDataCollectionEnabled`, `triggerEvent`, and `SDK_VERSION`, plus the TypeScript type `InAppMessaging`. Each runtime export is explained in the section that uses it. The type-only export is for typing only and is not demonstrated on the Expo screen.

# What does it do

Firebase In-App Messaging helps you engage your app's active users by sending them targeted, contextual messages that encourage them to use key app features. For example, you could send an in-app message to get users to subscribe, watch a video, complete a level, or buy an item. You can customize messages as cards, banners, modals, or images, and set up triggers so that they appear exactly when they'd benefit your users most.

<YouTube id="5MRKpvKV2pg" />

Most setup happens in the Firebase Console. Published campaigns are fetched and displayed by the native SDKs. This module exposes a small JavaScript API to suppress display, control automatic data collection, and trigger campaigns programmatically.

# Limitations

Firebase In-App Messaging allows only **one campaign per day** on app foreground or app launch triggers (see [firebase-ios-sdk#4768](https://github.com/firebase/firebase-ios-sdk/issues/4768)). That limit reduces accidental overload for non-contextual messages. Contextual triggers (Analytics events or programmatic `triggerEvent`) are not subject to that daily foreground/launch rate limit.

Native SDKs also fetch campaigns on a low-frequency schedule (about once per day) to conserve power. Use the console **Test on Device** flow with a device Firebase installation ID when iterating.

# Usage

Create and publish campaigns under [In-App Messaging](https://console.firebase.google.com/project/_/inappmessaging) in the Firebase Console (style, targeting, schedule, trigger events). Eligible devices show messages when a trigger fires and display is not suppressed.

## Package version

`SDK_VERSION` is the React Native Firebase In-App Messaging package version string exported from `@react-native-firebase/in-app-messaging`. The firebase-js-sdk does not export `SDK_VERSION` from a `firebase/in-app-messaging` entry point (that modular product does not exist).

```js
import { SDK_VERSION } from '@react-native-firebase/in-app-messaging';

console.log('In-App Messaging package version:', SDK_VERSION);
```

## Get an In-App Messaging instance

`getInAppMessaging(app?)` returns the `InAppMessaging` instance for the default app, or for the `FirebaseApp` you pass. This module does **not** support secondary Firebase apps: passing a non-default app throws. Prefer omitting `app` or passing `getApp()`.

```js
import { getApp } from '@react-native-firebase/app';
import { getInAppMessaging } from '@react-native-firebase/in-app-messaging';

function readInAppMessagingInstance() {
  const inAppMessaging = getInAppMessaging();
  const sameDefaultApp = getInAppMessaging(getApp());
  console.log('Default app name:', inAppMessaging.app.name);
  console.log('Same instance for default app:', sameDefaultApp === inAppMessaging);
  return inAppMessaging;
}
```

## Suppress message display

`isMessagesDisplaySuppressed(inAppMessaging)` reports whether rendering is currently suppressed. `setMessagesDisplaySuppressed(inAppMessaging, enabled)` enables or disables suppression.

When `enabled` is `true`, no in-app messages render until you set it back to `false` or the app restarts. Suppression is **not** persisted across restarts. Call it as early as possible if you need messages hidden during bootstrap (for example payment flows).

`setMessagesDisplaySuppressed` throws if `enabled` is not a boolean.

```js
import {
  getInAppMessaging,
  isMessagesDisplaySuppressed,
  setMessagesDisplaySuppressed,
} from '@react-native-firebase/in-app-messaging';

async function suppressDuringBootstrap() {
  const inAppMessaging = getInAppMessaging();
  await setMessagesDisplaySuppressed(inAppMessaging, true);
  console.log('Suppressed:', isMessagesDisplaySuppressed(inAppMessaging));
}

async function allowMessagesAfterSetup() {
  const inAppMessaging = getInAppMessaging();
  await setMessagesDisplaySuppressed(inAppMessaging, false);
  console.log('Suppressed:', isMessagesDisplaySuppressed(inAppMessaging));
}
```

## Automatic data collection

`isAutomaticDataCollectionEnabled(inAppMessaging)` reports whether automatic data collection is on. `setAutomaticDataCollectionEnabled(inAppMessaging, enabled)` enables or disables it at runtime.

This setting is **persisted** across app restarts and overrides the value from `firebase.json` / native manifests (`in_app_messaging_auto_collection_enabled` on Android via `firebase.json`, and the iOS Info.plist key applied from the same `firebase.json` flag). Use it for opt-in-first flows (for example GDPR).

`setAutomaticDataCollectionEnabled` throws if `enabled` is not a boolean.

```js
import {
  getInAppMessaging,
  isAutomaticDataCollectionEnabled,
  setAutomaticDataCollectionEnabled,
} from '@react-native-firebase/in-app-messaging';

async function enableCollectionAfterConsent() {
  const inAppMessaging = getInAppMessaging();
  await setAutomaticDataCollectionEnabled(inAppMessaging, true);
  console.log('Collection enabled:', isAutomaticDataCollectionEnabled(inAppMessaging));
}

async function disableCollection() {
  const inAppMessaging = getInAppMessaging();
  await setAutomaticDataCollectionEnabled(inAppMessaging, false);
  console.log('Collection enabled:', isAutomaticDataCollectionEnabled(inAppMessaging));
}
```

## Trigger an event programmatically

`triggerEvent(inAppMessaging, eventId)` requests any eligible campaigns whose programmatic trigger matches `eventId`. Create or note that event ID in the campaign Scheduling step in the console, then call `triggerEvent` with the same string.

`triggerEvent` throws if `eventId` is not a string.

```js
import { getInAppMessaging, triggerEvent } from '@react-native-firebase/in-app-messaging';

async function fireCampaignTrigger() {
  const inAppMessaging = getInAppMessaging();
  await triggerEvent(inAppMessaging, 'exampleTrigger');
  console.log('Triggered exampleTrigger');
}
```

## Types only (not runtime)

`InAppMessaging` is a TypeScript interface re-exported from `@react-native-firebase/in-app-messaging` for annotating the value returned by `getInAppMessaging`. It has no runtime value. Keep it out of the Expo example screen; import it with `import type` only when you need annotations in TypeScript source.

# firebase.json

## Disable collection of data

Set `in_app_messaging_auto_collection_enabled` in the project-root `firebase.json` so native builds start with automatic data collection off. Override later with `setAutomaticDataCollectionEnabled`.

```json
// <project-root>/firebase.json
{
  "react-native": {
    "in_app_messaging_auto_collection_enabled": false
  }
}
```
