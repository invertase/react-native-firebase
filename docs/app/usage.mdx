## Prerequisites

- `@react-native-firebase/app` installed and native config completed per [Getting Started](/) (Android `google-services.json`, iOS `GoogleService-Info.plist`, Expo config plugin, or React Native CLI setup). From v26, New Architecture is required for packages with a native bridge.
- Secondary-app examples below also import `@react-native-firebase/auth` to show passing a secondary app into another module. Install that package only if you use Auth: `npm install --save @react-native-firebase/auth` or `yarn add @react-native-firebase/auth`, then rebuild native apps.
- The Async Storage example uses `@react-native-async-storage/async-storage` (or any object with `getItem` / `setItem` / `removeItem`). Install it only if you call `setReactNativeAsyncStorage`: `npm install --save @react-native-async-storage/async-storage` or `yarn add @react-native-async-storage/async-storage`.

Example Expo Router screen: https://github.com/invertase/react-native-firebase/blob/main/test-expo/app/app.tsx

The App module ships with `@react-native-firebase/app` and provides:

- Creating [Secondary Firebase App Instances](/app/usage#secondary-apps).
- [Logging](/app/usage#logging) via `setLogLevel` and `onLog`.
- Wiring [Async Storage](/app/usage#async-storage) for Other/Hermes persistence paths.
- Reading [native meta and preferences](/app/usage#native-meta-and-preferences).
- Exposing [Utilities](/app/utils) to aid development.
- Configuring modules via [`firebase.json`](/app/json-config).

# Package version

`SDK_VERSION` is the React Native Firebase app package version string:

```js
import { SDK_VERSION } from '@react-native-firebase/app';

function logAppPackageVersion() {
  console.log('App package version:', SDK_VERSION);
}
```

# Default app

On Android and iOS the default Firebase app is created from native config during launch. Call `getApp()` with no arguments to use it. `getApp(name)` throws if that named app has not been initialized:

```js
import { getApp } from '@react-native-firebase/app';

function logDefaultApp() {
  const app = getApp();
  console.log('App name:', app.name);
  console.log('Project ID:', app.options.projectId);
  console.log('Data collection enabled:', app.automaticDataCollectionEnabled);
}
```

`FirebaseApp.name` and `FirebaseApp.options` are read-only. `automaticDataCollectionEnabled` is settable (GDPR opt-in/out for startup data collection when module-specific overrides are absent):

```js
import { getApp } from '@react-native-firebase/app';

function enableAutomaticDataCollection() {
  const app = getApp();
  app.automaticDataCollectionEnabled = true;
}
```

# Secondary Apps

You do not need to call [`initializeApp`](https://firebase.google.com/docs/web/setup#add-sdks-initialize)
with your default project credentials on Android and iOS. The native Android and iOS SDKs connect to your Firebase project using
the credentials provided during the [Getting Started](/) installation steps. The app module does provide support
for manually initializing secondary Firebase app instances (see also [Configure multiple projects](https://firebase.google.com/docs/projects/multiprojects)).

The native Firebase SDKs only provide functionality for creating secondary apps on the following services:

- [App Check](/app-check/usage).
- [Authentication](/auth/usage).
- [Realtime Database](/database/usage).
- [Cloud Firestore](/firestore/usage).
- [Cloud Functions](/functions/usage).
- [Cloud Storage](/storage/usage).
- [ML](/ml/usage).
- [Installations](/installations/usage).
- [Remote Config](/remote-config/usage).

## Initializing secondary apps

The module exposes an `initializeApp` method which accepts arguments containing the credentials and options for your secondary
apps. Replace the placeholder credential strings with values from the Firebase console for that secondary project:

```js
import { initializeApp } from '@react-native-firebase/app';

// Secondary Firebase project credentials (replace placeholders).
const credentials = {
  clientId: '1234567890-abc.apps.googleusercontent.com',
  appId: '1:1234567890:ios:abcdef123456',
  apiKey: 'AIzaSyExampleApiKeyForSecondaryApp',
  databaseURL: 'https://my-secondary-project.firebaseio.com',
  storageBucket: 'my-secondary-project.appspot.com',
  messagingSenderId: '1234567890',
  projectId: 'my-secondary-project',
};

const config = {
  name: 'SECONDARY_APP',
};

async function createSecondaryApp() {
  const secondaryApp = await initializeApp(credentials, config);
  return secondaryApp;
}
```

If you use multiple platforms, select the credentials for the platform that is running:

```js
import { initializeApp } from '@react-native-firebase/app';
import { Platform } from 'react-native';

// Secondary Firebase project credentials for Android (replace placeholders).
const androidCredentials = {
  clientId: '1234567890-android.apps.googleusercontent.com',
  appId: '1:1234567890:android:abcdef123456',
  apiKey: 'AIzaSyExampleAndroidApiKey',
  databaseURL: 'https://my-secondary-project.firebaseio.com',
  storageBucket: 'my-secondary-project.appspot.com',
  messagingSenderId: '1234567890',
  projectId: 'my-secondary-project',
};

// Secondary Firebase project credentials for iOS (replace placeholders).
const iosCredentials = {
  clientId: '1234567890-ios.apps.googleusercontent.com',
  appId: '1:1234567890:ios:abcdef123456',
  apiKey: 'AIzaSyExampleIosApiKey',
  databaseURL: 'https://my-secondary-project.firebaseio.com',
  storageBucket: 'my-secondary-project.appspot.com',
  messagingSenderId: '1234567890',
  projectId: 'my-secondary-project',
};

const config = {
  name: 'SECONDARY_APP',
};

async function createSecondaryAppForPlatform() {
  const credentials = Platform.select({
    android: androidCredentials,
    ios: iosCredentials,
    default: androidCredentials,
  });

  const secondaryApp = await initializeApp(credentials, config);
  return secondaryApp;
}
```

Once created, confirm the app instance exists by reading `getApps()`:

```js
import { getApps } from '@react-native-firebase/app';

function listApps() {
  const apps = getApps();

  apps.forEach(app => {
    console.log('App name: ', app.name);
  });
}
```

## Switching app instance

Switch app instances by calling `getApp` with the secondary app name, then pass that app into another module:

```js
import { getApp } from '@react-native-firebase/app';
import { getAuth } from '@react-native-firebase/auth';

function currentUserOnSecondaryApp() {
  const secondaryApp = getApp('SECONDARY_APP');
  return getAuth(secondaryApp).currentUser;
}
```

Or pass the `FirebaseApp` returned from `initializeApp` directly:

```js
import { initializeApp } from '@react-native-firebase/app';
import { getAuth } from '@react-native-firebase/auth';

async function currentUserFromInitializedApp() {
  const credentials = {
    clientId: '1234567890-abc.apps.googleusercontent.com',
    appId: '1:1234567890:ios:abcdef123456',
    apiKey: 'AIzaSyExampleApiKeyForSecondaryApp',
    databaseURL: 'https://my-secondary-project.firebaseio.com',
    storageBucket: 'my-secondary-project.appspot.com',
    messagingSenderId: '1234567890',
    projectId: 'my-secondary-project',
  };

  const config = {
    name: 'SECONDARY_APP',
  };

  const secondaryApp = await initializeApp(credentials, config);
  return getAuth(secondaryApp).currentUser;
}
```

## Deleting instances

Delete a secondary instance with `deleteApp` (or `app.delete()` on the instance):

```js
import { deleteApp, getApp } from '@react-native-firebase/app';

async function deleteSecondaryApp() {
  const secondaryApp = getApp('SECONDARY_APP');
  await deleteApp(secondaryApp);
}
```

# Logging

Use `setLogLevel` to control which Firebase SDK log messages are emitted. Accepted levels: `debug`, `verbose`, `info`, `warn`, `error`, `silent`. All levels at or above the current setting are captured (for example, `info` includes `warn` and `error`, but not `debug`):

```js
import { setLogLevel } from '@react-native-firebase/app';

function enableDebugLogs() {
  setLogLevel('debug');
}
```

Use `onLog` to install a custom log handler. The callback receives a `LogCallbackParams` object (`level`, `message`, `args`, `type`). Optional `LogOptions` can constrain which levels call your handler. Pass `null` to clear the handler:

```js
import { onLog } from '@react-native-firebase/app';

function installLogHandler() {
  onLog(
    ({ level, message, args, type }) => {
      console.log(`[${type}] ${level}: ${message}`, ...args);
    },
    { level: 'warn' },
  );
}

function clearLogHandler() {
  onLog(null);
}
```

`LogCallback`, `LogCallbackParams`, and `LogOptions` are TypeScript types exported from `@react-native-firebase/app` for typing `onLog` handlers.

# Async Storage

`setReactNativeAsyncStorage` wires an Async Storage implementation into the firebase-js-sdk Other/Hermes persistence path (Auth sessions, Analytics device IDs, and similar). Call it during bootstrap before you rely on that persistence. On Android and iOS native SDKs handle their own storage; this hook matters for Other platforms and shared JS persistence paths.

```js
import { setReactNativeAsyncStorage } from '@react-native-firebase/app';

function configureAsyncStorage() {
  // Replace with: import AsyncStorage from '@react-native-async-storage/async-storage'
  // then pass AsyncStorage. The object must implement getItem / setItem / removeItem.
  const asyncStorage = {
    getItem: async _key => null,
    setItem: async (_key, _value) => {},
    removeItem: async _key => {},
  };

  setReactNativeAsyncStorage(asyncStorage);
}
```

If you do not call `setReactNativeAsyncStorage`, an in-memory implementation is used and persisted JS state is lost on restart.

# Native meta and preferences

These helpers talk to React Native Firebase native stores (Info.plist / AndroidManifest meta, `firebase.json` constants, and shared preferences). They have no firebase-js-sdk modular equivalents.

Read native meta (plist / manifest) entries with `metaGetAll`:

```js
import { metaGetAll } from '@react-native-firebase/app';

async function logNativeMeta() {
  const meta = await metaGetAll();
  console.log('Native meta:', meta);
}
```

Read the baked-in `firebase.json` constants with `jsonGetAll` (see also [Firebase JSON Config](/app/json-config)):

```js
import { jsonGetAll } from '@react-native-firebase/app';

async function logFirebaseJsonConstants() {
  const json = await jsonGetAll();
  console.log('firebase.json constants:', json);
}
```

Read, write, and clear React Native Firebase native preferences:

```js
import {
  preferencesClearAll,
  preferencesGetAll,
  preferencesSetBool,
  preferencesSetString,
} from '@react-native-firebase/app';

async function nativePreferencesExample() {
  await preferencesSetBool('expo_demo_flag', true);
  await preferencesSetString('expo_demo_label', 'invertase');
  const all = await preferencesGetAll();
  console.log('Preferences:', all);
  await preferencesClearAll();
}
```

# `registerVersion` (web only)

`registerVersion` exists for API parity with the web SDK. On React Native Firebase it always throws; native SDK version registration is handled by the Firebase iOS and Android SDKs.

```js
import { registerVersion } from '@react-native-firebase/app';

function tryRegisterVersion() {
  // This call throws on React Native: "registerVersion is only supported on Web".
  registerVersion('my-library', '1.0.0');
}
```
