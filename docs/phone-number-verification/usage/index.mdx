## Prerequisites

- `@react-native-firebase/app` installed and native config completed per [Getting Started](/) (Android `google-services.json`, Expo config plugin, or React Native CLI setup). From v26, New Architecture is required for packages with a native bridge.
- **Android only.** This module wraps the Firebase Phone Number Verification Android SDK. There is no iOS or web modular API. Calling any exported function when `Platform.OS !== 'android'` throws: `Firebase Phone Number Verification is only supported on Android.`
- Install Phone Number Verification: `npm install --save @react-native-firebase/phone-number-verification` or `yarn add @react-native-firebase/phone-number-verification`, then rebuild the Android app.
- Enable Phone Number Verification in the [Firebase console](https://console.firebase.google.com/) (Security > Phone Verification). Production use needs billing, SHA-256, and OAuth brand verification as described in the official Android guides linked below.

Example Expo Router screen: https://github.com/invertase/react-native-firebase/blob/main/test-expo/app/phone-number-verification.tsx

# Installation

This module requires that the `@react-native-firebase/app` module is already setup and installed. To install the "app"
module, view the [Getting Started](/) documentation.

```bash
# Install & setup the app module
yarn add @react-native-firebase/app

# Install the phone-number-verification module
yarn add @react-native-firebase/phone-number-verification
```

> **Android only.** Rebuild the Android app after installing. There is no iOS pod step for this package.

# What does it do

Firebase Phone Number Verification provides carrier-level phone number verification on Android without SMS codes. It reads the phone number assigned to the device SIM from the carrier after user consent, then returns a signed JWT your backend can validate.

Key capabilities:

- **Carrier-level verification**: Verifies phone numbers with the mobile carrier, without SMS.
- **Support detection**: `getVerificationSupportInfo` checks device and carrier support without user consent.
- **Verified phone number**: `getVerifiedPhoneNumber` runs consent and returns a `VerifiedPhoneNumberTokenResult` (phone number, JWT, timestamps, nonce, claims).
- **Digital Credential API**: `getDigitalCredentialPayload` and `exchangeCredentialResponseForPhoneNumber` support a custom flow when you drive Android Credential Manager yourself.

## Region and carrier limitations

Phone Number Verification depends on carrier cooperation. Not all carriers or regions participate. Before relying on it, call `getVerificationSupportInfo()`. If a SIM slot returns `reason: 'INCAPABLE_DUE_TO_CARRIER_UNSUPPORTED'`, fall back to another method (for example Firebase Auth SMS).

Common `VerificationSupportStatus` reason strings:

{/* prettier-ignore */}
| Reason | Meaning |
| --- | --- |
| `CAPABLE` | The SIM's carrier supports Phone Number Verification. |
| `INCAPABLE_DUE_TO_CARRIER_UNSUPPORTED` | The carrier does not participate. |
| `INCAPABLE_DUE_TO_ANDROID_VERSION` | The device Android version is too old. |
| `INCAPABLE_DUE_TO_SIM_STATE` | No SIM, or the SIM is unusable. |
| `CAPABILITY_STATUS_UNSPECIFIED` | The SDK could not determine the status. |

# Usage

## Check verification support

`getVerificationSupportInfo(simSlot?)` is a React Native Firebase export (no firebase-js-sdk modular equivalent). It returns one `VerificationSupportResult` per SIM slot (or for the optional 0-based `simSlot`). It does not require user consent.

```js
import { getVerificationSupportInfo } from '@react-native-firebase/phone-number-verification';

async function readVerificationSupport() {
  const supportInfo = await getVerificationSupportInfo();

  for (const info of supportInfo) {
    console.log('SIM slot:', info.simSlot);
    console.log('Supported:', info.isSupported);
    console.log('Carrier ID:', info.carrierId);
    console.log('Reason:', info.reason);
  }

  return supportInfo;
}
```

### Query a specific SIM slot

On dual-SIM devices, pass a slot index:

```js
import { getVerificationSupportInfo } from '@react-native-firebase/phone-number-verification';

async function readSupportForSlotZero() {
  const supportInfo = await getVerificationSupportInfo(0);
  console.log('Slot 0 results:', supportInfo);
  return supportInfo;
}
```

### Fallback when unsupported

Guard Android, check support, then call verification or fall back:

```js
import { Platform } from 'react-native';
import {
  getVerificationSupportInfo,
  getVerifiedPhoneNumber,
} from '@react-native-firebase/phone-number-verification';

async function verifyWithSmsFallback() {
  if (Platform.OS !== 'android') {
    throw new Error('Use SMS or another method on non-Android platforms.');
  }

  const supportInfo = await getVerificationSupportInfo();
  const supported = supportInfo.some(info => info.isSupported);

  if (!supported) {
    throw new Error('Phone Number Verification unsupported; use SMS or another method.');
  }

  return await getVerifiedPhoneNumber();
}
```

## Verify a phone number

`getVerifiedPhoneNumber()` is a React Native Firebase export (no firebase-js-sdk modular equivalent). It presents the Android consent UI, then returns a `VerifiedPhoneNumberTokenResult`. Prepare the user with a short in-app explanation of why the phone number is needed before calling it. Official guidance: [Get started on Android](https://firebase.google.com/docs/phone-number-verification/android/get-started?utm_source=invertase&utm_medium=react-native-firebase&utm_campaign=phone-number-verification).

```js
import { getVerifiedPhoneNumber } from '@react-native-firebase/phone-number-verification';

async function verifyPhoneNumber() {
  const result = await getVerifiedPhoneNumber();
  console.log('Phone number:', result.phoneNumber);
  console.log('Token:', result.token);
  console.log('Expires at:', new Date(result.expirationTimestamp * 1000));
  console.log('Issued at:', new Date(result.issuedAtTimestamp * 1000));
  console.log('Nonce:', result.nonce);
  console.log('Claims:', result.claims);
  return result;
}
```

The returned `VerifiedPhoneNumberTokenResult` includes:

- `phoneNumber` — verified phone number in E.164 format.
- `token` — raw JWT string for server-side validation.
- `expirationTimestamp` — expiration as Unix epoch seconds.
- `issuedAtTimestamp` — issued-at as Unix epoch seconds.
- `nonce` — nonce from the JWT payload, or `null`.
- `claims` — all JWT claims as a key-value map, or `null`.

Send the token (not only the phone number) to your backend and verify it there. Backend JWT verification is covered in [Verify Firebase Phone Number Verification tokens](https://firebase.google.com/docs/phone-number-verification/verify-tokens?utm_source=invertase&utm_medium=react-native-firebase&utm_campaign=phone-number-verification); this page does not embed server samples.

## Custom verification with Digital Credentials

`getDigitalCredentialPayload(nonce)` and `exchangeCredentialResponseForPhoneNumber(dcApiResponse)` are React Native Firebase exports (no firebase-js-sdk modular equivalent). Use them when you need finer control over Android Credential Manager than the single-call `getVerifiedPhoneNumber()` flow. Official overview: [Customize the flow on Android](https://firebase.google.com/docs/phone-number-verification/android/custom-flow?utm_source=invertase&utm_medium=react-native-firebase&utm_campaign=phone-number-verification).

Between the two calls you own the Credential Manager request (Kotlin or other native code). That middle step is outside this JavaScript module. The React Native helpers take a `nonce` string and a Credential Manager response JWT string only (no privacy-policy URL argument on the React Native Firebase surface).

```js
import {
  exchangeCredentialResponseForPhoneNumber,
  getDigitalCredentialPayload,
} from '@react-native-firebase/phone-number-verification';

async function runCustomDigitalCredentialFlow(credentialManagerResponseJwt) {
  const nonce = 'your-unique-nonce-from-your-server';
  const payload = await getDigitalCredentialPayload(nonce);
  console.log('Digital credential payload for Credential Manager:', payload);

  const result = await exchangeCredentialResponseForPhoneNumber(credentialManagerResponseJwt);
  console.log('Phone number:', result.phoneNumber);
  console.log('Expires at:', new Date(result.expirationTimestamp * 1000));
  return result;
}
```

## Error handling

Failed calls reject with a native Firebase error. TypeScript callers can narrow with the `PnvError` interface (`code` is a `PnvErrorCode` string). `PnvErrorCode` is a runtime object of string constants exported from `@react-native-firebase/phone-number-verification` (no firebase-js-sdk modular equivalent).

{/* prettier-ignore */}
| Error code | Meaning |
| --- | --- |
| `pnv/carrier-not-supported` | The SIM's carrier does not support Phone Number Verification. |
| `pnv/invalid-digital-credential-response` | The Digital Credential API response was invalid. |
| `pnv/integrity-check-failed` | Device integrity check failed. |
| `pnv/preflight-check-failed` | Server-side preflight check failed. |
| `pnv/unsupported-operation` | The API call is not supported with the given parameters. |
| `pnv/credential-manager-error` | Android Credential Manager failed unexpectedly. |
| `pnv/invalid-test-number-id` | Test number IDs are empty, expired, or duplicated. |
| `pnv/test-session-already-enabled` | `enableTestSession` was called more than once. |
| `pnv/activity-context-required` | An Activity context is required (app may be in the background). |
| `pnv/unknown` | An unclassified native failure. |

```js
import {
  PnvErrorCode,
  getVerifiedPhoneNumber,
} from '@react-native-firebase/phone-number-verification';

async function verifyWithStructuredErrors() {
  try {
    const result = await getVerifiedPhoneNumber();
    console.log('Phone number:', result.phoneNumber);
    return result;
  } catch (error) {
    const code =
      error && typeof error === 'object' && 'code' in error ? String(error.code) : undefined;

    switch (code) {
      case PnvErrorCode.CARRIER_NOT_SUPPORTED:
        console.log('Fall back to SMS verification.');
        break;
      case PnvErrorCode.ACTIVITY_CONTEXT_REQUIRED:
        console.log('Retry when the app is in the foreground.');
        break;
      default:
        console.error('Phone Number Verification error:', code, error);
    }

    throw error;
  }
}
```

## Testing with a console test token

`enableTestSession(token)` is a React Native Firebase export (no firebase-js-sdk modular equivalent). It enables test mode without a physical SIM, using a console-generated test token (7-day lifetime). Call it once per app instance before other verification calls. A second call rejects with `pnv/test-session-already-enabled`.

Setup summary from the official Android get-started guide:

1. Generate a test token in the Firebase console (Security > Phone Verification > Testing).
2. Grant the Firebase Phone Number Verification Admin role needed to create test sessions if you are not the project owner.
3. Enroll the test device in the Google system services public beta when required for test mode.
4. Call `enableTestSession` once with that token.

```js
import {
  enableTestSession,
  getVerifiedPhoneNumber,
} from '@react-native-firebase/phone-number-verification';

async function verifyInTestSession(testTokenFromConsole) {
  await enableTestSession(testTokenFromConsole);

  const result = await getVerifiedPhoneNumber();
  console.log('Test phone number:', result.phoneNumber);
  return result;
}
```

In test mode, phone numbers use a valid country code followed by all zeros. Remove `enableTestSession` from production builds; production also requires the console production-upgrade steps on the [production mode](https://firebase.google.com/docs/phone-number-verification/android/production-mode?utm_source=invertase&utm_medium=react-native-firebase&utm_campaign=phone-number-verification) page.

## Platform handling

Every exported runtime function throws on non-Android platforms with: `Firebase Phone Number Verification is only supported on Android.` Guard call sites when you ship a multi-platform app:

```js
import { Platform } from 'react-native';
import { getVerificationSupportInfo } from '@react-native-firebase/phone-number-verification';

async function readSupportOnAndroidOnly() {
  if (Platform.OS !== 'android') {
    console.log('Phone Number Verification is Android only.');
    return [];
  }

  const supportInfo = await getVerificationSupportInfo();
  console.log('Support info:', supportInfo);
  return supportInfo;
}
```
